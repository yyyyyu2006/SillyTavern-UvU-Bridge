# UvU Story Bridge for SillyTavern

This project is a local, opt-in bridge between the UvU phone UI and SillyTavern. It keeps online UvU turns and offline SillyTavern scenes as separate, source-tagged records. It does not rewrite either app's base prompt.

## Current status

Version 0.5.1 clarifies the default TT file workflow, validates file target IDs and rejects static Pages relay addresses. Changing the TT mode is a pending choice until **保存 TT 连接**; a visible notice identifies the saved/current and selected modes, and sync plus mode-dependent operations pause until saved or reverted.

Version 0.5.0 adds TauriTavern Host ABI 2 support, a private self-hostable HTTPS relay, and reviewed offline JSON exchange. See [TT/iOS installation, deployment and operation](docs/tt-deployment.md). TT defaults to **无需服务器的文件交接**: install the UI extension, export UvU JSON, import and review it in TT, start/end a scene, download the return JSON, then import and approve it in UvU. The file target IDs are read from the validated packet. No Termux, Node backend, endpoint or pairing code is required for this workflow. The panel hides ST backend instructions and shows relay/admin controls only after selecting optional HTTPS mode. Existing saved HTTPS connections remain selected. No public relay or bundled secret is provided; physical iPhone/iPad execution is not yet verified. Original Node Tavern installation below remains available.

The repository includes the SillyTavern UI extension, local server plugin, protocol tests, and the reusable browser client at `client/uvu-bridge-client.js`. The matching UvU-side connection panel is maintained in the separate UvU app repository; users need a UvU deployment that includes that integration for end-to-end use.

The repository contains both parts required by the bridge:

- A SillyTavern UI extension for pairing, mode control, memory context, and scene export.
- A SillyTavern server plugin that exposes the authenticated local API used by UvU.

SillyTavern server plugins run with server-side privileges. Review the source before installing and only enable server plugins if you trust it.

## Intended behavior

- Online mode leaves normal UvU chat behavior unchanged.
- When connected, UvU checks the mapped character's mode before generating a reply. Offline mode blocks the UvU reply; the phone mode allows it.
- Successful UvU turns are sent to the local bridge as continuity records. The server does not call an LLM or rewrite UvU prompts.
- Offline scene mode captures the selected SillyTavern chat only after the user starts a scene.
- UvU messages are held as source-tagged memory events; they are not silently inserted into the SillyTavern chat transcript.
- SillyTavern scene exports are delivered to the mapped UvU character's existing memory-journal list as a draft. They are not injected by default; enabling the UvU setting uses its existing favorited-memory path.
- Memory injection is opt-in and uses SillyTavern's extension-prompt facility, not edits to the character card or base prompt.
- Switching modes never deletes either app's source conversation.

## SillyTavern Node installation overview

**TT users:** skip this section and follow the [file workflow](docs/tt-deployment.md#file-handoff-without-a-server). TT has no SillyTavern Node backend. Optional realtime operation needs a separately deployed private relay with a server, domain and TLS; your UvU / GitHub Pages URL is not a relay.

Install the repository twice because the UI extension and server plugin run in different parts of SillyTavern:

1. Add the repository URL in SillyTavern's third-party extension installer to install the UI panel.
2. Clone the same repository into `<SillyTavern>/plugins/uvu-story-bridge` for the server plugin.
3. From that plugin directory, run `node setup-server-plugin.js`. The script asks for the exact HTTPS UvU origin, displays the changes, and applies them only after the user types `APPLY`. It backs up `config.yaml` and any existing `server/config.json`, enables server plugins, and adds the origin to the bridge allowlist. The client API listens on a separate loopback-only port (default `8765`), so the setup does not disable CSRF or change SillyTavern's global CORS settings. Restart SillyTavern afterward.
4. In UvU's **酒馆互通** page, enter the local bridge address and paste the short-lived pairing code generated by the SillyTavern UI panel, then click **连接 / 配对**.
5. Pairing publishes the UvU character ID/name directory to the local bridge. In SillyTavern, choose the matching UvU character from the dropdown for the currently selected Tavern character. The panel displays both sides of the mapping; starting a scene is blocked if the UvU character is not verified in the directory.
6. In UvU, hand off the selected range from the intended character/archive. In Tavern, browse and review received entries, then explicitly press **设为下场记忆来源** before starting a scene. Browsing another archive during an active scene never changes its pinned memory source or export destination. Start a scene to lock the character, chat and source archive; **拿出手机** opens the UvU message channel. End the scene in SillyTavern to export it to the mapped UvU character's review draft. Review and save the selected text in UvU before it becomes usable diary memory.

## Data and security

- The API is intended for a SillyTavern instance on the same device as UvU.
- Cross-origin requests require an explicit origin allowlist and a paired bearer token; the separate client API binds only to `127.0.0.1`.
- Pair codes expire and can only be redeemed once. Tokens can be revoked from either side.
- The plugin rejects non-loopback clients by default.
- Local event and memory records are stored under `server/data/`, which is excluded from Git.
- Do not expose the SillyTavern server port to the public internet. CORS is not authentication.

## 0.4.0 reliability update

Update both the UI extension and `plugins/uvu-story-bridge`, restart Tavern normally, then refresh its page. The initial version label now comes from the loaded extension version. Checking versions does not install an update.

- Reviews and scenes are persisted with confirmed writes to a separate per-account plugin file. Concurrent tabs use revision checks rather than silently overwriting each other. The original Tavern settings remain a compatibility mirror.
- Replay coalesces revisions before comparing source text, retaining approved edits when the latest original has not changed. Changed originals require review again.
- Capacity is 500 received copies; an oversized first transfer saves what fits and reports the remainder. Delete unwanted received copies and refresh again. No automatic eviction occurs.
- Deleted copies remain deleted on ordinary refresh. Explicit recovery restores only the viewed archive as unreviewed copies while retained events exist. Missing queue history must be handed off again from source.
- Per-transfer receipts distinguish relay acceptance from receiver retention, review, deletion skips and incomplete delivery. They contain counts and source identity, not extra chat turns.
- Phone-mode handoffs cover the frozen completed turn, including replies longer than eight messages. Revised source messages are retransmitted.
- UvU offers explicit recovery after relay reset or queue gaps; existing diaries remain, incomplete scenes are never injected.
- Scene boundaries use a verified source anchor; removing earlier messages cannot silently shift export. Missing/edited/ambiguous anchors stop export. Legacy scenes without anchors must be ended without export before starting a new scene; source chat remains available.
- Only derived copies are filtered. Base prompts, character cards and other extension prompts are unchanged. Selected memory has a visible 12000-character budget, with bounded excerpts and an actual-injection preview.
- Background browser suspension can delay delivery; foreground polling resumes from persisted cursors. Physical Android/iOS behavior still requires device verification.

## 0.4.1 permanent pairing

In Tavern expand **永久配对与已绑定设备**, generate a permanent code, then paste it into UvU's pairing field and give the browser a device name. The 32-character random code is reusable until reset; the server stores only its hash and shows the plaintext only when generating it. Refreshing loses the displayed plaintext, not the code's validity. Reset if forgotten. The five-minute one-time code remains available.

Each pairing creates an independent device token; existing legacy tokens survive the upgrade and additional pairings. Resetting the permanent code affects new pairing only. Revoke one device or confirm revoke-all separately; these preserve original chats, approved memory and the permanent code. At most 50 new device credentials are retained; remove unused devices before adding more. Do not distribute your permanent code.

UvU stores its credential in the current browser, retries transient failures while visible with bounded backoff, and stops automatic retries after 401. Closing the page or restarting Tavern does not remove the binding. Clearing site data or deleting server data does. A changed bridge endpoint requires a fresh pairing and never receives the old credential. Browser suspension can delay retries. Multiple credentials share the local relay and directory; separate UvU databases are not merged.

Update both extension and server to 0.4.1, restart Tavern normally and refresh both pages. Original prompt assembly and model-generation code are unchanged in this release.

## 0.4.2 whole-floor story review

Scene export retains one review item per original Tavern message floor, including speaker, source floor number and timestamp. Long floors split only for transport and are reconstructed before review. Explicit body wrappers take precedence over outside panels. Automatic aliases: content, maintext, main_text, main-text, 正文, 正文内容, 正文部分, story, storytext, story_text, story-content, story_content, narrative and narration. The first matched wrapper type wins. The panel's optional body-tag field overrides this list for custom presets; extra exclusions still apply. Arbitrary preset markup cannot be universally inferred. Untagged text remains for manual review with a warning. A recognized but malformed wrapper stops export.

UvU offers per-scene select-all, partial selection, collapsed whole-floor rows and editable text. Saving puts only selected edited text into the existing diary/memory record, categorized as 酒馆线下剧情. Existing character/archive injection switches and vector opt-in still apply. No original chat, prompt or generation code is replaced.

Legacy timestamp transcripts are regrouped by speaker/time boundaries; unstructured old text stays one manual-review record. Already imported unapproved paragraph reviews expose an explicit regroup action, which discards only unsaved review edits after confirmation. Approved records are never automatically rewritten; stripped legacy tags cannot be recovered. Frozen legacy exports retain their previous format for reliable retry. Update extension, server and UvU together to 0.4.2, restart the server and refresh both pages.
